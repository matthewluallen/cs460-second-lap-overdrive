# Drive code versus original Android apps — 13 November 2026

Baseline: `c148060`, branch `slipstream-and-security-hardening`, PR #4. This is a static APK/SDK comparison plus executable tests of our code. No APK or firmware was executed, no car was connected, and no physical behavior was validated in this pass. The latest observed spinning remains unexplained.

## Evidence and independent techniques

Primary artifact: Fast & Furious `com.anki.foxtrot`, build 403. Existing provenance/signature limits are in [FAST-FURIOUS-REVIEW.md](FAST-FURIOUS-REVIEW.md).

Cross-check artifact: standard Overdrive APK 1502, SHA256 `b38cfb62e99b7d530f8a58da74cf6ba3cd62c88a426707e3022cdbb05ab97155`; extracted ARM library SHA256 `88bbb08b2226826d599cffde4b60c693ab460ae86f7e25eed5c862b615887778`. This second binary was used to independently verify the scalar offset conversion, not to claim a whole-app comparison across both versions.

Public SDK revision: `410352617b8660338746a6bb2b2dd173afb1b91a`, [manufacturer repository](https://github.com/anki/drive-sdk/tree/410352617b8660338746a6bb2b2dd173afb1b91a). Its C serializers already supply independently compiled packet vectors in `protocol-review.test.mjs`.

The review combines existing Ghidra 12.2 native exports, JADX Java exports, fresh LLVM Thumb disassembly, and an independent Capstone 5.0.7/ELF literal verifier. Ghidra's ARM soft-float parameter recovery is demonstrably imperfect: a localization acquisition output argument is absent from its rendered caller, and speed constructor arguments appear with incorrect types. Critical claims below were checked at the instruction/call/literal level. All native addresses below are Ghidra addresses; ELF virtual addresses in LLVM/Capstone are 0x10000 lower for the F&F image.

The new read-only [audit utility](../tools/audit-native-offset.py) verifies the reviewed instruction pattern, literal addresses and float constants without loading or executing native code. Its [retained output](NATIVE-OFFSET-EVIDENCE.json) confirms both binaries classify **raw offset greater than 500000 as unknown**, preserve the 654321 sentinel and otherwise scale millimeters to meters. An unrecognized instruction pattern fails instead of declaring equivalence. Local proprietary binaries, decompiled bodies, artwork and audio are not included in Git.

## Confirmed defects and repairs

|---|---|---|
|D1 — STOP dispatch and ordering|`setSpeed(300); safetyStop(...)` before yielding still entered the radio with 300 before 0. A second case let a fresh 150 request overwrite an undelivered STOP behind an already-entered 300 write, producing 300 → 150.|A command epoch is checked at the final boundary before transport entry. STOP/close/fault invalidate old positive/lateral work even if recovery occurs immediately. Zero-speed commands have a separate priority queue entry, so a later intention cannot replace the STOP barrier. A genuinely already-entered GATT write remains uncancellable; the test requires STOP next, then the fresh request.|
|D2 — stale or invented calibration evidence|A previous optical pair survived STOP/recover, off-road/recovery, map replacement and long gaps. Automatic corrections retain the exact optical observation that authorized them and recheck it before transport entry. A newer observation, loss, STOP, recovery, map change or expiry invalidates unsent corrections. Throttling begins at actual transport entry, so discarded work cannot starve a newer correction. The F&F configuration further shows why one native tuning value is not universal: Groundshock inherits base-car lane speed 0.99 m/s, while truck base uses 0.22 m/s; upgrades and active state affect native selection. Slipstream's 350 mm/s lane request is a deliberate current choice, not a value proved exact for every model. These source values are **not a recommendation to increase speed**.

## Physical evidence and remaining acceptance

The accepted repaired scan and failed reference-spin trial sent identical 300 mm/s forward packet bytes. The former calibrated after its first code; the latter remained at unknown offset during locked acquisition. They also differed in connection history and starting section. None of D1–D5 establishes the cause of that spin: its recording contains no new offset, lane or turn command. Fixing real defects must not be presented as a diagnosed firmware repair.

The next hardware baseline should use a freshly power-cycled charged car, recording from initialization, the currently safeguarded normal scan path and the established 300 mm/s ceiling. No guessed starting offset, new 0x35 command or widened watchdog is justified. If stable scanning succeeds, a reviewed forward-only mapped controller should suppress lane/turn intent without accidentally suppressing the intended calibration policy. Require repeated stable laps and STOP/restart before left/right completion, speed variation, racing or attacks. If the baseline fails, inspect or compare the physical car/track under controlled conditions instead of repeating the unchanged attempt.

## Validation

Baseline on Node 22.23.5/npm 11.9.0: **664/664 Node tests passed** before this pass. Final: **697/697 Node tests pass**, **38 Python tests pass** on Python 3.14.7, CWE/dependency regression checks pass and `npm audit` reports **0 vulnerabilities**. The new native verifier independently passes against both local libraries. Raw hardware fixtures remain unchanged.

Two broader regression corrections are deliberately distinguished from APK parity. The replay helper now drains the real command queue between time steps instead of pretending the entire recording arrives before the first queued write can complete. Combat tests use fixed seeds 1, 6, 34, including reproduced watchdog and ambiguous-location paths, and assert truthful localization/targetability throughout rather than incorrectly demanding a unique location at every final sample.

The Story matrix exposed a genuine planner/deadline incompatibility: at the old midpoint pace, a car could wait a circuit for a safe lane request and finish only 2/3 tasks in 90 s without a pit. Story CPU guidance now chooses 95% of the **existing phase maximum**, preserving 5% headroom, all scoring bounds, goals, deadlines, geometry checks and operator caps. At ceiling 400 this requests 171 mm/s for scanning/delivery and 228 mm/s for carrying. All 24 mission combinations now pass (three missions × two layouts × one through four cars). Their 10-second telemetry allowance remains explicitly simulator-only; Figure-eight additionally isolates mission logic from the physical steering policy and remains blocked for physical Story acceptance. This is independent game guidance, not native planner reconstruction or hardware speed validation.

Native evidence verification is static; software tests and geometric checks do not constitute firmware formal verification or hardware acceptance.
